# 修复后回调统计与现场限制

已收到 27 条定位观察记录，全部满足本文的快照匹配条件。其中 `first_entry` 的 8 条所在定义窗口已闭环，`refresh` 的 19 条所在窗口未闭环。整场统计状态为 `incomplete`，不能表述为完整回调验收通过。定位数据匹配不代表考勤业务通过，本次未提交考勤。

本报告公开计数、校验规则与质量结论，去除设备标识、进程和会话标识、个人与单位信息、地址及坐标、Wi-Fi 和基站值、快照标识。含个人、单位和地址信息的现场截图不公开，也不随报告附上原始数据。

采集只观察下游 `i71.d(String, boolean, DtLocation)`：钉钉原方法使用原参数执行一次后，比较收到的 DTO 与模块当前读取的快照，保留原方法的返回值和异常。观察器不主动请求定位，不改定位参数、结果或快照；这只是该观察点的记录范围。来源按 DTO 的 `ServiceType` 区分，阶段由采集控制标记。

匹配口径如下：

| 项目 | 判定规则 |
| --- | --- |
| `coordinate_match` | 经纬度分别换算为局部米制差值，各方向均不超过 5.001 米，并处理经度环绕。这里不是圆形半径 5 米的判定。 |
| `precision_match` | 高度与精度值分别相等。 |
| `address15_match` | 15 个地址字段逐项比较。双侧均空算一致，空值与非空值算不一致；不公开字段值。 |
| `match` | 上述三项同时成立。 |

15 项地址字段为 `District`、`PoiName`、`Country`、`BuildingId`、`AdCode`、`Description`、`CityCode`、`Street`、`Province`、`Floor`、`Address`、`City`、`Road`、`AoiName`、`StreetNum`。15 项一致不代表每项都有非空内容。原方法异常、观察异常和空值另行计数，不以定位匹配替代这些检查。

| 阶段 | 来源 | 已收到回调 | match | mismatch | 不可比较 | 定义窗口闭环 |
| --- | --- | ---: | ---: | ---: | ---: | --- |
| `first_entry` | SYSTEM | 7 | 7 | 0 | 0 | 是 |
| `first_entry` | GAODE | 1 | 1 | 0 | 0 | 是 |
| `refresh` | SYSTEM | 19 | 19 | 0 | 0 | 否 |
| 合计 | 已观测来源 | 27 | 27 | 0 | 0 | 整场不完整 |

27 条已收到记录的坐标、高度/精度和地址字段比较均匹配。记录内的观察异常、空 DTO、空快照和原方法异常计数均为 0。这些计数不包含未观测到的时间段，也不等于采集过程没有发生错误。

已收到的记录通过序列与检查点校验，没有发现缺号、重复或乱序，计数等式成立。`first_entry` 在切换到下一阶段时封闭，其 7 条 SYSTEM 加 1 条 GAODE 合计 8 条可以在该定义窗口内对账。这个窗口从观察器就绪、阶段标记生效后开始；“first_entry”这一名称不代表已经覆盖进程冷启动以来的所有首次回调。

`refresh` 收到了 19 条 SYSTEM 记录，但终止 summary 请求超时，最终汇总未能持久化。已收到的检查点累计值与增量一致，但没有有效终止汇总覆盖刷新尾段。随后还记录到卸载观察器取消，因此不能把已收到记录内的零观察异常描述为整场“零错误”。最终质量标志为：

- `sequence_and_checkpoint_checks_pass = true`
- `count_equation_pass = true`
- `all_run_final_summaries_verified = false`
- `all_defined_stage_windows_closed = false`
- `process_lifetime_complete = false`

存在观察器尚未就绪的启动缺口，以及终止未闭环的缺口。缺口内回调数量未知，应写为未知，不能写成 0。`refresh` 未收到 GAODE 记录，也不能据此断言整个刷新过程中没有 GAODE 调用。因此，27/27 仅表示已经收到并可比较的记录均匹配，不能证明全进程、全阶段或所有业务结果通过。

现场曾出现标题为“温馨提示”的弹窗，提示原文为：

> 当前手机疑似安装风险插件进行虚拟打卡，请卸载或关闭风险插件后重新打卡。

按钮为“取消”和“拍照证明”。这条风险提示与定位观察点的 `match` 是不同的业务事实。没有提交打卡、签到或拍照证明，没有执行绕过风险检测的操作。

出现提示后，已停止扩大 Frida 测试，清理临时诊断服务及端口转发，恢复临时屏幕常亮设置，并结束钉钉进程后重新启动。用户反馈：“没有风险提示，位置正常。”该反馈支持提示与诊断环境相关的判断；但诊断环境清理、应用重启、时间变化同时发生，没有分别控制变量，不能证明某个组件是唯一原因，也不能把提示确定归因于 Frida。

清理后的对照依据是用户反馈，没有补充截图核验。后续结论保留这一证据边界和因果不确定性，不因位置显示正常就推断考勤业务通过。
