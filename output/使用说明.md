# 锤锤 API 102 迁移测试版

文件：`app-general-api102-test1.apk`

这是基于你提供的“锤锤 0.4-beta5”APK 制作的个人迁移测试版，版本号为 `0.4-beta5-api102-test1`。需要支持 **libxposed API 102** 的框架；不再使用传统 Xposed API，也不兼容仅支持 API 100/101 的框架。请以框架显示的 API 版本为准，而不是仅看 LSPosed 的版本名称。

## 安装和测试

1. **先备份，再卸载旧版。** 将 `/sdcard/Android/data/com.fuck.android.rimet/files/profiles` 中的快照复制到应用数据目录以外，例如电脑或 Download 中。卸载可能连同该目录一起删除。不要只在原目录里留一份备份。
2. 本版使用新的本地测试签名，无法直接覆盖作者签名的旧版。备份完成后卸载旧版，再安装本版。
3. 在支持 API 102 的框架中启用模块，选择需要作用的目标应用。重新安装后检查作用域是否仍正确。
4. 打开模块，恢复或创建快照，重新选择需要使用的快照。应用连接框架后会把选中的快照同步到 Remote Preferences；原来的勾选状态不会自动随快照文件备份恢复。
5. 强行停止并重新打开目标应用，然后检查实际功能。本版未启用 API 102 热重载，更换 APK 后应重启目标进程。

## 已做的迁移

- 新增 `XposedModule` 入口，使用 `onModuleLoaded` 和 `onPackageReady`。
- 用 API 102 的 `hook(...).intercept(...)` 重写六处 Hook，删除旧入口及传统 Xposed API 依赖。
- 将目标进程读取快照的方式改为框架 Remote Preferences；应用侧接入官方 service 102.0.0。
- 激活检测改为检查实际服务连接及其 API 版本，不再 Hook 模块自身。
- 定位回调保留原监听器对象；返回值采用目标应用的定位对象类型，避免类加载器冲突。
- 保留原有快照序列化格式及界面资源；每次使用读取当前配置，避免永久缓存首次选择的快照。

已进行 Java 编译、DEX 构建、APK v2/v3 签名校验、最终二进制清单检查、DEX 依赖检查及 ZIP 对齐检查；原 APK 的 Kotlin 服务注册文件也已逐项核对保留。

JVM 测试使用真实 API 102 接口和模拟框架，覆盖 Hook 注册和去重、空配置调用原方法、空及继承监听器、可恢复的单个 Hook 失败、配置连接重试、应用在不提供模块 API 时的类加载、定位对象跨类加载器转换及快照不被修改。

**没有连接手机，尚未验证 ART Hook、真实 Binder 配置同步、快照创建或目标应用运行效果。** JVM 测试不能替代这些真机测试。本版不承诺兼容所有 Android 版本或所有高德 SDK 版本。

## 高德 Key 与新签名

原 APK 内置了高德 SDK Key。Key 如果绑定作者的包名及签名，新签名可能使“创建快照”的高德定位鉴权失败；API 102 迁移并不能解决高德服务端的授权绑定。

本版签名 SHA-1：

```text
28:C5:BB:EB:95:5A:DA:DB:56:38:97:E0:05:56:3B:4B:B6:8A:86:E4
```

包名：`com.fuck.android.rimet`。如果出现高德鉴权错误，需要申请与你的包名、上述签名匹配的 Android SDK Key，替换构建资源中的 `amap_api_key` 后重新构建。原版 Key 目前保持不变。不要为规避签名检查而删除系统校验。

## 出错时提供的信息

框架模块日志中搜索 `Smartisan102`，正常加载应能看到 `API 102 module loaded`、`LoadPackage` 和 `Hook installed`。应用侧的 `Remote snapshot synchronized` 在 Android 日志中，框架的模块日志不一定包含应用侧日志。

若仅界面提示未激活，等待服务连接后重新打开模块确认。若功能无效，请提供 Android 版本、框架分支及 API 版本、目标应用版本，以及 `Smartisan102` 对应的错误日志。日志中出现 `Snapshot sync failed` 时，先重新打开模块并重新选择快照。

## 源码和重建

- 新代码：`migration/src/`
- 可重复执行的 APK 修改及构建脚本：`migration/build.py`
- JVM 测试：`migration/test.py` 和 `migration/tests/`
- 最终 APK 静态校验：`migration/verify_apk.py`
- 依赖来源和 SHA-256：`tools/migration/dependencies.json`
- 输出 APK 的 SHA-256：`output/build-result.json`

在工作目录执行（需要 Python 3.12、JDK 17，以及本目录已有的工具和依赖）：

```powershell
python migration/build.py
python migration/test.py
python migration/verify_apk.py
```

构建每次从原始 APK 解码，校验原 APK SHA-256，并生成独立的构建目录。`decoded/` 和 `analysis/` 下的检查材料不会被用作修改后的源 APK。签名文件保存在 `migration/signing/local-test.p12`；保留它可让后续个人测试版互相覆盖安装。它是本地测试密钥，不是作者的发布密钥。

接口依据：[libxposed API](https://github.com/libxposed/api)、[libxposed service](https://github.com/libxposed/service)。本次使用 Maven Central 发布的 `102.0.0` 依赖。
